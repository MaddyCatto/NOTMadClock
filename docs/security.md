# Локальный аудит безопасности — 9 ноября 2026

Основа: рабочий коммит PR #4 `7900cab` (включает PR #3). При начале аудита GitHub
не содержал более поздних изменений. Сохранены Deep Purple, десять независимых
расписаний, DAILY/ONCE, общий штрихкод, отдельный Audio FGS и бездействие в ожидании.
Это проверка конкретной версии и границ доверия, а не сертификация MASVS или
утверждение об отсутствии уязвимостей.

## Методика и границы доверия

Использованы категории [OWASP MASVS v2.1.0](https://github.com/OWASP/masvs/releases/tag/v2.1.0)
(STORAGE, PLATFORM, CODE, PRIVACY, NETWORK, CRYPTO) и принципы Android Security:
[минимальные разрешения и IPC](https://developer.android.com/privacy-and-security/security-tips),
[неэкспортируемые компоненты](https://developer.android.com/privacy-and-security/risks/android-exported),
[immutable PendingIntent](https://developer.android.com/privacy-and-security/risks/pending-intent),
[правила backup](https://developer.android.com/identity/data/autobackup),
[безопасная подпись](https://developer.android.com/studio/publish/app-signing).
Версия MASVS сверена с официальным GitHub Releases. Прямое чтение Android Developer
из облачной среды блокируется политикой доменов; ссылки приведены как нормативные
ориентиры, без заявления об онлайн-проверке каждой страницы на дату аудита.

Доверенные стороны — Android, установленная пара с одной подписью и владелец
сертификата. Произвольные другие приложения и выбранный файловый провайдер не
считаются доверенными. Штрихкод, имя файла, URI и внешние описания уязвимостей
обрабатываются как данные: никакие команды из них не исполняются. Корневой доступ,
компрометация ОС/ключа подписи и доступ владельца устройства через debug-инструменты
не входят в обеспечиваемую этой схемой изоляцию. Антирут, телеметрия и сеть не добавлены.

## Подтверждённые недостатки и исправления

| Недостаток | Исправление и практический предел |
| --- | --- |
| Импорт песни не имел ограничения фактических байтов; размер провайдера не заслуживает доверия | `SongImport` читает буфером 64 КиБ, считает фактические байты и прекращает импорт свыше 200 МиБ **до записи лишних байтов**. Пустой/недоступный/слишком большой файл включает существующий запасной сигнал Audio. Весь файл не загружается в RAM. |
| Прерванный процесс мог оставить `.tmp` и бесхозные песни | При следующем создании Audio Service очищаются только его `import-*.tmp` и неактивные `song-*.audio`; активный кэш сохраняется. В обычном завершении копирования временный файл удаляется независимо от результата. Никакого idle-cleaner нет. |
| START с другим, ещё не завершённым ID мог заменить играющий сеанс | Пока Audio имеет активный UUID, конфликтующий START отклоняется. Штатный Main начинает следующий UUID только после STOP ACK. Повторный START того же UUID идемпотентен; tombstone защищает от START завершённого UUID после перезапуска. |
| STOP не проверял допустимую форму ID; неправильные extras/сохранённый JSON могли вызвать исключение | Одинаковые границы ID (1–80 букв/цифр/дефисов), content URI с authority (до 8192 символов), громкости 1–100 и штрихкода (до 8192 символов). Некорректные команды/JSON не исполняются; валидные карточки сохраняются. Чтение испорченной записи не перезаписывает исходное содержимое. |
| Исключение провайдера/MediaPlayer могло вывести путь к песне в logcat | Для импорта/воспроизведения/запуска сохраняются общие причины или класс исключения; произвольные тексты исключения с URI не логируются. Штрихкод и содержимое JSON не логируются. |
| Явный READ URI grant помощнику оставался после завершения сеанса | Main сохраняет URI вместе с pending STOP и отзывает grant конкретному пакету после ACK. Поздний повторный ACK не отзывает доступ следующего сеанса к той же песне. Старый pending STOP без URI остаётся совместимым. |
| `allowBackup=false` не описывал отдельно современные device-transfer правила | Для обоих пакетов добавлены XML-исключения всех доменов cloud backup/device transfer и legacy backup. Приватные песни/код/active state не предназначены для резервного переноса. Поведение OEM всё равно проверяется на устройстве. |
| Транзитивная `com.google.guava:guava:33.3.1-android` совпала с опубликованной GHSA | Минимальная версия основной Android-зависимости повышена до `33.7.2-android`, исправляющей [GHSA-xxph-c9ww-hj94](https://github.com/advisories/GHSA-xxph-c9ww-hj94). Это ресурсный DoS при Java-десериализации; собственный код не использует ObjectInputStream, эксплуатация в MadClock не подтверждена. Исправлены также test-only Guava/BC зависимости Robolectric; они не добавлены в APK. Другие обновления ради косметики не выполнялись. |
| Actions использовали перемещаемые теги; отсутствовал путь постоянной release-подписи | Actions зафиксированы полными SHA, checkout не сохраняет credentials, добавлены CodeQL и проверка разрешённых Gradle-координат. Release-подпись обоих модулей берётся из одного внешнего keystore; ключи не входят в репозиторий, PR CI или артефакты. |

Некорректные данные приватного хранилища не считаются удалённой атакой. Защита от
падения при их чтении нужна для надёжности; восстановить повреждённую песню,
утраченный штрихкод или удалённые настройки приложение не может.

## APK, IPC и хранение

`check_apks.py` разбирает **собранные** manifests через Android apkanalyzer,
проверяет сертификаты через apksigner и проверяет оба пакета:

- Нет INTERNET и ACCESS_NETWORK_STATE, sharedUserId и лишних экспортируемых
  компонентов. У Main нет playback FGS, WAKE_LOCK, POST_NOTIFICATIONS, звукового
  уведомления или собственного плеера. Зависимости не возвращают эти разрешения.
- Main экспортирует только launcher Activity. Она не принимает команды звука
  из входных extras. Receiver расписания и внутренние Activity не экспортированы;
  служебные ContentProvider библиотек тоже закрыты. У AndroidX ProfileInstaller
  остаётся штатный экспортированный receiver с системным `android.permission.DUMP`.
- Audio экспортирует только сервис и setup Activity, оба под `signature`
  `CONTROL_AUDIO`. Launcher Activity/alias отсутствует, setup исключена из Recents.
  Android проверяет разрешение **до** доставки Intent; `Binder.getCallingUid()`
  внутри асинхронного onStartCommand для проверки исходного отправителя не применяется.
- Main проверяет сертификат целевого Audio через PackageManager перед передачей
  URI и команд. Нет неявного IPC или возвращаемых произвольных Intent. ID — не
  замена signature-защите. Защита ACK остаётся capability Binder ResultReceiver,
  передаваемого только доверенному помощнику, и проверкой pending UUID.
- AlarmManager использует явные immutable PendingIntent с отдельным data URI на
  постоянный UUID. Generation отсекает старые доставки; одноразовые срабатывания
  потребляются до звука. Сертификат и snapshot UUID не зависят от lifecycle Main.
- Песни импортируются только из content URI с явно выданным READ grant. Рабочие
  файлы и SharedPreferences остаются в приватных каталогах своих UID. Файлового
  провайдера для их публикации нет. У Main остаётся его собственный persistable
  grant для будущих будильников; завершение Audio его не отзывает.

Никакого общего каталога настроек между пакетами, eval, WebView для штрихкодов,
SQL-команд из данных, внешнего сервера или собственного шифрования не добавлено.
ОС изолирует приватные данные. Штрихкод является условием штатной остановки через
UI, но не защищает от Force Stop, удаления данных, root/ADB или системной остановки.

## Автоматические проверки

Локально: полный прогон **101 тест** (63 Main + 38 Audio), затем 16 адресных
тестов усиленной проверки подписи/URI grant; ошибок нет. Оба debug APK собраны,
оба Lint завершились без ошибок (38 предупреждений Main и 1 Audio). Оставшиеся
предупреждения включают KTX/SwitchCompat, overdraw, синхронные записи маленького
состояния, текст сканера и новую версию тестовой зависимости; baseline не добавлен.
Проверены **263 разрешённые координаты**, включая транзитивные, unit tests и
build tools: в APK/test runtime advisories не осталось, 13 сборочных координат
с известными advisories остаются в явном отчёте ниже.
[Машиночитаемый результат с хешами локальных APK](security-audit-2026-11-09.json).

```sh
gradle :app:assembleDebug :audio:assembleDebug :app:testDebugUnitTest :audio:testDebugUnitTest :app:lintDebug :audio:lintDebug securityDependencyInventory --no-daemon --max-workers=4
python3 scripts/check_apks.py
python3 scripts/check_dependencies.py
```

Новые негативные тесты проверяют неверные ID/схемы URI/громкость/extras/ACK,
недоступный/пустой/повреждённый файл, поток свыше 200 МиБ, повреждённый JSON,
конфликтующий и запоздалый START/STOP, очистку временных копий, неправильную или
отсутствующую подпись помощника, непротекание URI в собственные логи и отзыв
URI grant только после соответствующего STOP ACK. Существующие проверки
десяти расписаний, сканирования/STOP, повтора и громкости сохранены.

Неподписанный реальный отправитель, пытающийся обратиться к helper Service,
не может быть достоверно проверен прямым вызовом onStartCommand в Robolectric:
это обход системной доставки Intent. Автоматика проверяет protectionLevel и
реальные manifests; реальное отклонение чужого UID требует устройства/эмулятора.
Негативный тест Main также доказывает, что helper с чужой/пустой подписью не
получает команд и разрешений URI. Эти разные гарантии не смешиваются.

`securityDependencyInventory` сохраняет разрешённые транзитивные Maven-координаты
APK, unit-тестов и build tools. `check_dependencies.py` проверяет версии через
официальную GitHub Global Security Advisories API, сохраняет JSON с датой, scope
и результатами. CI останавливается при advisories в APK или unit-test runtime.
Сборочный classpath проверяется и публикуется отдельно как предупреждение;
`python3 scripts/check_dependencies.py --strict-build-tools` включает отказ и для него.
Это явная граница проверки, а не исключение находок из отчёта. Ошибка сети/API не превращается в успешный пустой результат.
Покрытие GitHub Maven advisories неполное; отсутствие совпадений не доказывает
отсутствие неизвестных/неопубликованных уязвимостей. Android SDK, ОС, Gradle runtime
и бинарные базы сканера этой Maven-проверкой не исчерпываются.

В используемом AGP/Kotlin build classpath остались опубликованные advisories:
Guava 33.3.1-jre, Netty 4.1.110.Final (шесть модулей), Commons Compress 1.21,
jose4j 0.9.5, Bouncy Castle 1.79 (два модуля), JDOM 2.0.6 и Kotlin Gradle plugin
2.2.20. Это **13 координат сборочных инструментов**, отсутствующих в APK.
HTTP/TLS/архивные/PKI пути этих библиотек и работа сборочного процесса требуют
отдельного анализа достижимости; отсутствие INTERNET в APK их не защищает на
машине сборки. Эксплуатация в текущей сборке не подтверждена, но риск не объявлен
устранённым. Подробные GHSA и scopes сохраняются в JSON. Рабочий vendor build stack
не переписывался подменой десятков его транзитивных компонентов.

Для [GHSA-r937-wjx7-w2jp](https://github.com/advisories/GHSA-r937-wjx7-w2jp) API
указывает первую исправленную версию Kotlin `2.4.20-Beta1`. Переход на beta-компилятор
вместе с заменой совместимого AGP выходит за безопасный объём этого изменения.
Явно выставлено `org.gradle.caching=false`, удалённых build caches в проекте нет,
CI изолирован и не получает release-секретов. Это снижение риска пути build cache,
а не утверждение, что уязвимость библиотечного кода исправлена. Для production
сборки нужен доверенный хост, проверенные исходники/артефакты/ключи и отдельное
плановое обновление поддерживаемого Gradle/Kotlin/AGP стека с полным регрессионным
тестированием. Maven-проверка не сканирует все внутренние библиотеки Gradle runtime.

В CI добавлен CodeQL `java-kotlin`, manual build и security-extended, с публикацией
результата в GitHub code scanning. Локального CodeQL CLI в среде нет; факт выполнения
и выводы CI необходимо сверять по конкретному запуску PR. В build job доступны
чтение исходников/метаданных Actions и загрузка security events; release-ключей в PR CI нет.
Dependabot отслеживает SHA Actions и security updates Gradle без потока обычных
version-update PR. Это не включает произвольные секреты или автослияние.

## Независимый статический анализ APK

Оба локальных debug APK проверены **MobSF v4.6.4**, официальный image
`opensecurity/mobile-security-framework-mobsf@sha256:cf1465a3cc0c95488b9a6cdb1c7799d4b576d391ee28232c221f6a196bf2f74c`.
Контейнер запускался с `--network none`, `MOBSF_DOMAIN_MALWARE_SCAN=0`,
`MOBSF_VT_ENABLED=0`, `MOBSF_VT_UPLOAD=0`; онлайн-проверка доменов/репутации и
VirusTotal не выполнялись. Анализ использовал декомпиляцию, manifest/certificate,
code patterns и проверку native ELF. JSON взят из ответа локального `/api/v1/scan`.
Результаты сопоставлены с SHA-256 фактических локальных APK. Дополнительно manifests
и наличие v2-подписи подтверждены независимым Androguard 4.1.4.

Разбор предупреждений MobSF:

- High: `debuggable=true` и debug certificate у обоих APK. Это реальные свойства
  **тестовых** сборок; их нельзя считать production-сборками. Подпись тестовых APK
  намеренно не заменена. Release собирается с debuggable=false и внешней подписью.
- Warning: minSdk26 позволяет установку на устаревшие ОС; минимальная версия не
  повышалась ради оценки сканера. Целевое устройство работает на Android 16.
- Warning: protectionLevel системного DUMP нельзя определить из APK; это системное
  разрешение, а не незащищённый собственный receiver. Signature-защита Audio
  распознана сканером как защищённая.
- Info: присутствует logging. Ручная проверка и негативные тесты проверяют именно
  содержание собственных логов, а не удаляют нужную диагностику.
- Warning: восемь vendor ELF по четырём ABI не демонстрируют fortified-функции.
  Это ограничение сторонних CameraX/ML Kit binaries, не доказательство конкретного
  переполнения. NX/PIE/canary/RELRO проверены сканером; native-код полностью не аудирован.
- Эвристика «possible secrets» Main обнаружила 34 высокоэнтропийные строки.
  Они сопоставлены со сторонними native-библиотеками, математической константой
  Guava и строкой CameraX quirk. Приватных signing-ключей/пользовательских кодов
  в APK не найдено. Это не заменяет анализ исходников всех native-зависимостей.
- Статическая база MobSF не обнаружила известных ей trackers в обоих APK. Это
  ограниченный результат базы, а не доказательство отсутствия всего библиотечного
  кода статистики. Фактическое отсутствие INTERNET проверено независимо.

Не выполнялся динамический анализ MobSF. Успешный статический анализ не подтверждает
звуковую надёжность на OxygenOS и не делает итоговое приложение «полностью безопасным».

## Постоянная release-подпись

Оба модуля применяют `gradle/release-signing.gradle`. Владельцу нужно самостоятельно
настроить следующие переменные через безопасное окружение/хранилище секретов:

| Переменная | Значение |
| --- | --- |
| MADCLOCK_KEYSTORE_PATH | Путь к существующему внешнему keystore |
| MADCLOCK_KEYSTORE_PASSWORD | Пароль keystore |
| MADCLOCK_KEY_ALIAS | Один постоянный alias для обоих APK |
| MADCLOCK_KEY_PASSWORD | Пароль ключа |

Не передавайте приватный ключ/пароли в чат, исходники, аргументы Gradle `-P`,
логи, PR CI или артефакты. Новые release-ключи не создавались и не запрашивались в рамках этого
аудита. Файлы keystore/signing properties добавлены в .gitignore. Нужны защищённое
хранение и резервная копия ключа у владельца; потеря ключа мешает обновлениям.

При настроенных переменных:

```sh
gradle :app:assembleRelease :audio:assembleRelease --no-daemon
python3 scripts/check_apks.py --variant release
```

Проверяется общая подпись обоих APK и отсутствие debuggable у release. Частичная
конфигурация отвергается; assembleRelease/bundleRelease без переменных завершается
ошибкой. Не распространяйте промежуточный unsigned APK от неуспешной сборки.
Проверка отказа без ключа выполнена. Настоящая release-подпись не выполнялась:
внешний ключ владельца отсутствует. Debug-конфигурация и имеющийся локальный
сертификат не менялись; оба debug APK по-прежнему имеют общий сертификат.

**Переход с установленной debug-подписи на другой постоянный release-сертификат
Android не разрешает как обычное обновление. Может потребоваться переустановка
со стиранием настроек, штрихкода и песен в приватном кэше.** Обновление без потери
данных возможно только совместимой подписью. Разные запуски CI также могут иметь
разные debug-ключи; нельзя смешивать Main и Audio из разных комплектов.

## Проверка на устройстве и оставшиеся риски

Устройства/эмулятора в среде нет. Помимо [сценария будильников](alarms.md#протокол-oneplus-pad-3--oxygenos-16010--android-16),
на OnePlus Pad 3 необходимо проверить:

1. Реальный отказ стороннему UID: через тестовое приложение с другим сертификатом
   или `adb shell am start-foreground-service -n com.madclock.audio/.AudioService -a com.madclock.audio.STOP --es session invalid`
   ожидается отказ из-за CONTROL_AUDIO. Текущая музыка не меняется. Аналогично
   внешний broadcast не должен попасть в неэкспортируемый AlarmReceiver.
2. Импорт локальной нормальной песни, файла >200 МиБ, удалённого/отозванного URI,
   пустого/повреждённого файла; штатный fallback, отсутствие .tmp после следующего
   запуска и корректная остановка сканированием. Содержимое кодов/URI не появляется
   в собственных logcat-сообщениях.
3. Не менее пяти смахиваний основного MadClock, блокировку, громкость, повтор,
   DAILY/ONCE и пересечения. При правильном штрихкоде нет воскресшего сигнала.
4. Реальную ОС-изоляцию файлов, поведение backup/device transfer конкретной OxygenOS,
   межпакетный URI grant/отзыв после ACK и работу камеры. Robolectric не заменяет эти проверки.

Системный Force Stop, выключение через диспетчер сервисов, отзыв разрешений и
ограничения производителя остаются сильнее приложения. Скомпрометированный
сертификат даёт возможность доверенного IPC. Вредоносный/зависший файловый
провайдер способен задержать чтение: лимит байтов не является гарантией времени
отклика и не анализирует медиадекодеры Android. Приватное хранилище не защищает от
root/скомпрометированной ОС, а повреждённые/стёртые данные могут привести к пропуску
сигнала. Неизвестные уязвимости сторонних native-библиотек остаются вне гарантии
автоматических сканеров. Исправления не вводят постоянных сервисов в ожидании,
перезапусков по polling, ограничений длительности сигнала или новых зависимостей
основного приложения от lifecycle Activity.
