# MadClock — Android-будильник со штрихкодом

Прототип 0.1.0 для тестирования на **OnePlus Pad 3 / OxygenOS 16**.

## Возможности

- Ежедневный будильник в заданное время через Android `AlarmManager.setAlarmClock`.
- Одна выбранная локальная песня автоматически начинается после срабатывания и **повторяется без ограничителя длительности** до сканирования зарегистрированного штрихкода.
- Фоновый сервис воспроизведения и попытка показать экран будильника поверх экрана блокировки.
- Пока будильник работает, раз в 1,5 секунды проверяется громкость потока `STREAM_ALARM`. Если она ниже установленного уровня, приложение пытается её восстановить.
- Регистрация штрихкода или QR-кода камерой с ML Kit. Модель сканирования включена в APK, интернет при работе не нужен.
- Отдельный тестовый будильник через 1 минуту.
- Восстановление **будущего** ежедневного расписания после перезагрузки, изменения времени, смены часового пояса и обновления приложения.
- Нет серверной части, аккаунтов, сетевых разрешений, root и Google Play Developer.

## Как собрать APK без Android Studio / SDK на Windows

1. Скачайте и распакуйте архив проекта. Откройте папку `MadClock`.
2. На [github.com/new](https://github.com/new) создайте репозиторий `MadClock`. **Не выбирайте** создание README, лицензии или `.gitignore` — все файлы уже есть. Репозиторий можно сделать приватным.
3. В пустом репозитории нажмите **uploading an existing file** или **Add file → Upload files**. Перетащите **содержимое папки `MadClock`** в область загрузки. Не загружайте ZIP-файл как единственный файл: GitHub Actions не сможет его собрать. Убедитесь, что в корне репозитория видны `app/`, `build.gradle.kts`, `settings.gradle.kts`, а в папке `.github/workflows/` находится `android.yml`. GitHub может не перенести скрытую папку `.github` из некоторых файловых менеджеров — в Windows включите показ скрытых элементов, либо создайте файл `.github/workflows/android.yml` через **Add file → Create new file** и скопируйте содержимое из архива.
4. Нажмите **Commit changes**. Откройте вкладку **Actions → Build MadClock APK**. Если Actions отключены для репозитория, разрешите их. Дождитесь завершения сборки.
5. В успешной сборке в разделе **Artifacts** скачайте архив `MadClock-debug-APK`. Распакуйте его: внутри `app-debug.apk`.
6. Передайте `app-debug.apk` на OnePlus Pad 3 и откройте его. Разрешите установку приложений из этого источника, если Android запросит разрешение.
7. Выберите локальную песню и зарегистрируйте физический штрихкод, установите время и громкость. Выдайте разрешение на уведомления и полноэкранный будильник; проверьте настройки энергосбережения OxygenOS. Сначала запустите **тест через 1 минуту**, затем ежедневный режим.

**Важно:** GitHub хранит скачиваемый артефакт только 30 дней после сборки. Исходный код останется в вашем репозитории; APK можно собирать повторно через **Actions → Build MadClock APK → Run workflow**.

## Технические ограничения и аварийное выключение

- На Android нельзя гарантировать неотключаемость. `Настройки → Приложения → MadClock → Остановить принудительно` остановит звук и может отменить запланированные события. Android также позволяет останавливать foreground service из системного диспетчера активных приложений.
- Восстановление громкости — **попытка**, прошивка может запретить изменение громкости, особенно в режиме «Не беспокоить». Приложение не блокирует физические кнопки.
- Обработка полноэкранных уведомлений, доступ к камере и запуск фоновых сервисов зависят от разрешений Android и OxygenOS; гарантии до испытаний на планшете нет.
- После принудительной остановки Android обычно не позволяет приложению работать в фоне до следующего ручного запуска. Откройте MadClock и повторно сохраните будильник.
- При успешном сканировании приложение пытается вернуть системную громкость будильника к значению, которое было до запуска. После принудительной остановки восстановление может не произойти.
- Если выбранный аудиофайл оказался недоступен, вместо него проигрывается встроенный аварийный сигнал.
- Не используйте прототип в качестве единственного критически важного будильника, пока он не прошёл реальные ночные испытания. Звук в текущей версии не прекращается автоматически через 30 минут: требуется сканирование или системная остановка.
- APK от GitHub Actions — отладочная сборка (`debug`). Для личного тестирования подходит, для публикации потребуется отдельный релиз и ключ подписи.

## Техническая реализация

- Kotlin, Android SDK API 26–36 (target/compile 36).
- AGP 8.13.2 + Gradle 8.13, байткод Java 17; GitHub Actions использует JDK 21 для тестов Robolectric Android 16.
- CameraX 1.6.2 + ML Kit Barcode Scanning 17.3.0 (bundled).
- `USE_EXACT_ALARM` (Android 13+), `SCHEDULE_EXACT_ALARM` (Android 12–12L), `setAlarmClock`.
- `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, `USAGE_ALARM`, `MediaPlayer` loop, `PARTIAL_WAKE_LOCK`.
- Предусмотренные Android средства принудительной остановки приложения невозможно и не нужно блокировать.

## Проверочный сценарий

Подробности сохранения активного сигнала, восстановления после уничтожения
процесса и испытаний на OxygenOS: [устойчивость будильника](docs/alarm-recovery.md).

1. Зарегистрировать физически удалённый от кровати штрихкод и выбрать локальную песню.
2. Запустить тест через минуту и **заблокировать экран** планшета.
3. Убедиться, что основной звук включается без предварительного открытия приложения.
4. Погасить экран, свернуть приложение, удалить карточку из недавних — убедиться, что звук продолжает играть (прошивка может повести себя иначе).
5. Уменьшить громкость и проверить её восстановление примерно через 1,5–3 секунды.
6. Открыть уведомление или MadClock, отсканировать **неверный** код — звук должен продолжаться.
7. Отсканировать зарегистрированный код — звук должен прекратиться.
8. Проверить перезагрузку планшета, ночной режим энергосбережения и ежедневный запуск.
