# MadClock — два экспериментальных звуковых режима

Прототип для OnePlus Pad 3 / OxygenOS 16.0.10 / Android 16. Основной пакет
`com.madclock.app` управляет часами, настройками, точным расписанием и локальным
сканером штрихкода. Он **не воспроизводит аудио своим плеером**, не содержит
звуковой FGS, playback WakeLock или перезапусков после Recent Tasks.

## Режимы

- **A — системные уведомления.** До срабатывания заранее планируются 20 отдельных
  AlarmManager-событий через 30 секунд. Каждое просит Android озвучить уведомление
  встроенным `glass_signal_alarm_60s.mp3` (приложенный файл включён без изменений).
  Выбранная локальная песня в A не используется. Это конечная серия, а не
  бесконечное воспроизведение: последний запрос приходит через 9 минут 30 секунд.
  Android может ограничивать длительность звука, подавлять/прерывать повторные
  уведомления и применять cooldown/DND. Непрерывный 60-секундный звук не обещается.
- **B — MadClock Audio.** Отдельный APK `com.madclock.audio` копирует выбранную
  песню в своё частное хранилище и повторяет её в собственном mediaPlayback FGS.
  У помощника нет launcher-иконки или задачи воспроизведения в Recent Tasks.
  Уведомление сервиса и запись в системных настройках приложений остаются видимыми.
  URI и громкость передаются явно; настройки двух пакетов не являются общими.

Одновременно выбран только один режим. Перед первым звуком A установленный
помощник должен подтвердить остановку; B сначала отменяет уведомления A.
Правильный зарегистрированный код завершает текущий сеанс: в A отменяются все
его события и уведомление, в B отправляется защищённая STOP-команда. Ежедневное
расписание следующего дня при этом остаётся включённым. Неверный код не завершает
сеанс. Регистрация нового кода во время активного сигнала запрещена.

## Установка и первый запуск

1. В успешном GitHub Actions скачайте артефакт **MadClock-experimental-pair-debug**.
   Он содержит `MadClock-debug.apk` и `MadClock-Audio-debug.apk`, собранные и
   подписанные вместе. Не смешивайте APK из разных сборок с разными ключами.
2. Для B сначала установите **MadClock Audio**, затем основной **MadClock**.
   Помощник не появится среди launcher-иконок: управление и запрос разрешения
   уведомлений открываются из MadClock при выборе B и запуске теста.
   Для самостоятельного испытания A помощник можно вообще не устанавливать.
3. Зарегистрируйте штрихкод. Для B выберите локальную песню через системный
   файловый диалог. Разрешите точные будильники; для A — уведомления и звук
   канала «MadClock A». Для B разрешите уведомления помощнику и повторите тест
   после завершения диалога разрешения. Фоновая работа на OxygenOS настраивается
   отдельно для каждого установленного пакета.
4. Сначала запустите тест через минуту, затем ежедневный режим. Выбранный режим,
   песня, код и громкость фиксируются для этого запуска; будущие настройки
   не меняют условия остановки уже активного сигнала.

При установке с ADB:

```sh
adb install -r MadClock-Audio-debug.apk
adb install -r MadClock-debug.apk
```

Для обновления без потери данных нужен тот же ключ подписи, что у установленной
верссии. Debug-ключи разных CI-запусков могут различаться. Android не разрешает
обновление APK другим ключом; удаление приложения стирает его настройки.

## Сборка и проверки

Gradle 8.13, AGP 8.13.2, Kotlin 2.2.20, SDK 36. Для моделей Android 16 в
Robolectric нужен Java 21 runtime; байткод приложений остаётся Java 17.

```sh
gradle :app:assembleDebug :audio:assembleDebug :app:testDebugUnitTest :audio:testDebugUnitTest :app:lintDebug :audio:lintDebug --no-daemon --max-workers=4
python3 scripts/check_apks.py
```

APK: `app/build/outputs/apk/debug/app-debug.apk` и
`audio/build/outputs/apk/debug/audio-debug.apk`. Скрипт проверяет уже собранные
APK, подписи, разрешения, manifest IPC и точный SHA-256 встроенного MP3.
CI запускается и для pull request, публикует оба APK одним комплектом.

## Ограничения и испытания

Оба режима полностью локальные, сетевых разрешений нет. Камера использует
bundled ML Kit. Режим B сохраняет бесконечное повторение песни, контроль громкости
примерно каждые 1,5 секунды и встроенный запасной сигнал. В A громкость потока
будильников устанавливается при каждом событии; фонового регулятора в основном
приложении нет. Исходная громкость восстанавливается после штатной остановки.

Force Stop, остановка системным диспетчером, отзыв разрешений и ограничения
OxygenOS имеют приоритет. Отдельный APK снижает зависимость от задачи интерфейса,
но не делает сервис неубиваемым. A ограничен 20 событиями и возможностями
системного звука уведомлений. Не используйте прототип как единственный критичный
будильник до ночных испытаний. Зафиксируйте отдельно результаты A и B.
